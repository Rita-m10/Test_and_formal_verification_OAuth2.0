## Верификация протокола при помощи верификатора SPIN
Рассмотрим ситуацию, когда в работу протокола включается злоумышленник:
![Атака](https://github.com/user-attachments/assets/127d94a8-8067-418f-8ddc-6df4a0d44815)

В файле с расширением .pml можно найти модель данного протокола на языке Promela, в которую был введен злоумышленник. В конце файла описано требование к модели, которое мы хотим проверить при помощи верификатора.

!<>Int_success - "Никогда в будущем злоумышленник не узнает код авторизации"

Общая схема составления модели и ее верификации выглядит следующим образом:
1. Изучить спецификацию протокола
2. Определить процессы на основе участников протокола, между которыми передаются сообщения с данными
3. Добавить необходимые каналы для передачи сообщений между процессами
4. Определить переменные, которые будут использоваться процессами
5. Выделить структуру сообщений, передаваемых между процессами, и ввести типы данных для каждого вида сообщений
6. Описать логику каждого процесса. В структуре if, если несколько условий являются выполнимыми, то недетерминированно выбирается одно из них, это придаёт процессу симуляции случайный характер
7. Добавить процесс, представляющий собой злоумышленника, и соответствующие каналы связи
8. Описать поведение злоумышленника, который может перехватывать, модифицировать или отправлять сообщения
9. Просимулировать работу модели в верификаторе SPIN и проверить модель на работоспособность. Если были найдены ошибки, вернуться на шаг 6.
10. Сформулировать LTL-формулу, характеризующую требования, которые мы предъявляем к системе
11. Провести верификацию модели при помощи SPIN на выполнение сформулированных формул
12. Проанализировать результаты верификации

## Тестирование на наличие уязвимостей
В папке "Тестирование на наличие уязвимостей" собраны тесты на языке Python и коллекции запросов Postman для тестирования реализаций протокола OAuth от Authlib (https://github.com/authlib/example-oauth2-server/tree/master) и ВКонтакте.
Тесты представлены для таких уязвимостей:
1. Подмена URI-перенаправления
2. Повторное использование кода авторизации
3. Использование кода авторизации для другого клиента (только для Authlib)
4. Проверка времени действия токена доступа (только для Authlib, было уменьшено время жизни токена доступа до 5 секунд на сервере авторизации)


## Тестирование на соответствие спецификации
На основе спецификации составлен конечный автомат и доопределен до полностью определенного. 
![Автомат OAuth2 0](https://github.com/user-attachments/assets/ac899b11-a376-46e4-9a22-701924865860)

Он был минимизирован до трех состояний.
![Минимизированный_автомат](https://github.com/user-attachments/assets/abc330f1-94ff-459b-9b8a-becdeebd953b)

При помощи сервиса http://fsmtestonline.ru/ синтезированы тестовые последовательности методом обхода графа переходов и методом Василевского. Реализация подачи тестовых последовательностей написана на языке Python при помощи библиотеки Requests. Всё можно найти в папке "Тестирование на соответствие спецификации". Данную программу и тесты можно использовать для тестирования других реализаций, но в зависимости от исполнения необходимо изменить значения переменных auth_server и resource_server, а также в ответ на запрос кода авторизации сообщение об ошибке может передаваться как в параметре URL-перенаправления, так и в теле ответа. Также необходимо учитывать, что способ аутентификации пользователя может отличаться.
